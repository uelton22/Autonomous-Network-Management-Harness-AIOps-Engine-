### `cpu-dos-protect global`

> **Página:** 1932 · **Modo:** Configuration mode · **Privilégios:** Config · **Leitura (show/display):** não

**Description:** Update the maximum number of packets per second that the CPU should accept. Exceeding traffic will be discarded.

**Supported Platforms:** This command is not supported in the following platforms: DM4050, DM4250, DM4618, DM4920.

**Syntax:**

```text
cpu-dos-protect global max-pps
```

**Parameters:**

- `max-pps` — Maximum packets per second. — *Valores:* The allowed range depends on the hardware platform. See the hardware restrictions below. · *Default:* The default value depends on the hardware platform. See the
- `hardware restrictions below.`

**Default:** N/A

**History:**

| Release | Modification |
| --- | --- |
| 5.10 | This command was introduced. This command was enabled for DM4360, DM4370, DM4610, and 5.12 DM4615. |

**Usage Guidelines:**

This command can be executed directly via CLI. Example: This example shows how to configure the global rate limit.

```text
# cpu-dos-protect global max-pps 1500
(cpu-dos-protect)# commit
```

Commit complete.

```text
(cpu-dos-protect)#
```

**Impacts and precautions:**

Please select the maximum number of packets per second wisely, according to the active features and protocols. Using a value that is too low might cause the application to malfunction due to missing packets. In turn, picking an excessively high value might cause CPU overload during attacks or network loops, for instance.

**Hardware restrictions:**

The allowed range of values for DM4340 is 128 - 4992, with steps of 128 packets per seconds. For other platforms the allowed range is 100 - 5000. The default value for DM4770 is 3000 packets per second, For DM4340, the default value is 896 packets per second. For other platforms, the default value is 900 packets per second.


### `cpu-dos-protect protocols`

> **Página:** 1934 · **Modo:** Configuration mode · **Privilégios:** Config · **Leitura (show/display):** não

**Description:** Update the maximum number of packets per second per protocol that the CPU should accept. Exceeding traffic will be discarded.

**Supported Platforms:** This command is not supported in the following platforms: DM4050, DM4250, DM4618, DM4920.

**Syntax:**

```text
cpu-dos-protect protocols protocol_name max-pps max-pps-value
```

> _Use the no form to revert this command. For further information about the no form, read the chapter Using the "No" Form of a Command._

**Parameters:**

- `protocol_name` — Protocol name. — *Valores:* List of supported protocols: acl-based, arp, bfd, bgp, cfm, dhcp, eaps, erps, icmpv4_v6, igmp, in-band-mgmt, lbd, lldp, mpls-ldp, mpls-rsvp, ospf, pppoe, slow-protocols, snmp, stp, ttl-1, tunneling, unknown-hosts, vrrp-ipv4, vrrp-ipv6. · *Default:* N/A
- `max-pps max-pps-value` — Maximum packets per second. — *Valores:* 1 - 5000 · *Default:* The default value depends on the hardware platform.

**Default:** N/A

**History:**

| Release | Modification |
| --- | --- |
| 5.12 | This command was introduced. |
| 7.0 | The queue ACL-BASED for ACL redirect action was added. |
| 8.0 | The queue UNKNOWN-HOSTS was added. |
| 8.2 | The queue MPLS-RSVP was added. |
| 10.6 | The ICMPv4_v6 and SNMP queues were added. |

**Usage Guidelines:**

This command can be executed directly via CLI. Example: This example shows how to configure the protocol maximum rate limit for ARP protocol.

```text
# cpu-dos-protect protocols <protocol_name> max-pps 1500
# cpu-dos-protect protocols arp max-pps 1500
(cpu-dos-protect)# commit
```

Commit complete.

```text
(cpu-dos-protect)#
```

**Impacts and precautions:**

Please select the maximum number of packets per second wisely, according to the active features and protocols. Using a value that is too low might cause the application to malfunction due to missing packets. In turn, picking an excessively high value might cause CPU overload during attacks or network loops, for instance.

**Hardware restrictions:**

The CPU DoS protect feature uses UDP destination port 161 as the default for the SNMP protocol, according to RFCs 1157 and 1161. If this port is changed, the packet filter will not work for SNMP.
